= Adopt 0.7.0

Blueprint 0.7.0 intentionally changes configuration and public APIs before 1.0.
Upgrade the CLI, platform, imported core/provider packages and report consumers
as a coordinated change. Do not mix the 0.7 platform with an older CLI.

== Make ownership explicit

Package declarations continue to use checked constructors such as
`Packages("pkgs", From(NixPackages(...)))`. Declare each build's executor and
select it:

[source,roc,snippet=unchecked]
----
Packages("pkgs", From(NixPackages("github:NixOS/nixpkgs/nixos-unstable"))),
Source("assets", "path:./assets"),
Executor("native", Nix("pkgs")),
Environment("producer", [Tools(["pkgs#bash", "pkgs#coreutils"])]),
Build("assets", [
    Execute("native"),
    Use("producer"),
    Files(["scripts/produce.sh"]),
    Inputs(["assets"]),
    Run(["bash", "scripts/produce.sh"]),
    Output("dist/assets"),
]),
----

`Nix("pkgs")` names the declared package source the executor bootstraps from.
`Adapter(provider, source)` declares another provider's executor. The executor
no longer follows whichever package source is declared first.

`Input`, `Overlay` and `Source` declarations, and the Roc bundle sources that
`RocPackages` adds, belong to Nix without a `Resolver`. Write
`Resolver(provider, names)` only to assign one of them to another provider.
Core-owned `SourceFile` inputs need no resolver. Every referenced source and
executor must be declared; unsupported combinations fail rather than guessing
an owner. Keep compilation and packaging behavior in your scripts.

== Resolve current authority explicitly

Blueprint 0.7.0 reads the current Lock 2 contract. Earlier lock formats are
unsupported; there is no lock-conversion command or automatic upgrade path.

Update configuration and run `blueprint check`. Commands that read the lock
refuse an unsupported one, including `blueprint update NAME...`. A full
`blueprint update`, with no names, replaces it in place. Keep the old lock in
version history so that you can diff its pins against the new ones. Review and
commit the newly resolved lock as an explicit dependency change. The update
resolves the adopted configuration; it does not promise to reproduce an older
lock's dependency decisions.

Use reviewed immutable source references in configuration when you want to
constrain what resolution selects. Review the resulting pins and verification
evidence before adopting the new authority.

Generated state is disposable. Clear the project's generated `.blueprint/`
state when adopting 0.7.0. The next successful build establishes a fresh local
explanation baseline.

== Declare inputs with one setting

`Overlay(name, ref)` is gone. Declare every flake input with
`Input(name, ref)`; an environment that lists it in `Overlays` applies it as
an overlay, and the Nix resolver learns the input's role from that use. The
Spec records inputs as `{ name, url }` with no provider-specific kind.

== Behavior changes to check

* `blueprint update` refuses a project that declares a package source for a
  provider this CLI does not register, such as a Guix source, with
  `no registered resolver for guix`.
* An environment with no tools takes its bootstrap package set from the
  source of a Nix executor that a Build selects, when any Build selects one,
  and otherwise from the first declared Nix source.
* Nix owns the `roc-<hash>` sources of Roc packages that builds use without a
  `Resolver`, as it owns `Input`, `Overlay` and `Source` declarations.
* `blueprint check` asks each executor's provider to validate its declaration.
  A Nix executor needs a non-empty bootstrap package source.
* Every fetched entry of the lock records the hosts that served its bytes and
  the address a published digest was read from. A host the lock did not name,
  declared or reached by a redirect, is reported before the lock is written.
* A tree in the store is verified against its recorded digest on every use
  and rebuilt from its archive when it differs. Programs are exposed through
  symbolic links, or copies on Windows, never hard links. Clear the store if
  an older one holds trees without records; they are rebuilt once.
* `blueprint env NAME` prints what entering a shell exports, as data.

== Use current report and library contracts

* Lock report format 2 exposes `content_identity` for pinned input content.
  Compare it together with its provider.
* `LockSnapshot.source_content_identity` returns the provider-qualified
  `ContentIdentity` value from the current lock projection.
* Build result schema 2 exposes `build_identity` for the fully prepared native
  build request. Its comparison domain also includes the provider. The result
  carries `snapshot_digest`; the snapshot itself is in the `plan` and
  `explain` JSON.
* Validate current lock projections with `lock-snapshot-v2.schema.json`.

Use the CLI, platform, imported packages and report consumers from the same
current contract. A content identity, build identity, original-file/tree/output
digest and result path answer different questions; they are not interchangeable.

Spec major 3 defines explicit ownership and executor declarations. Lock and
report formats carry their own versions; they are not determined by package
version 0.7.0. Check the relevant version before consuming data.

== Use the integrated build interface

Use `blueprint plan build NAME` for declared relationships and add `--prepare`
for an exact build identity. Use `blueprint explain build NAME [--prepare]` to
compare against the last successful local build. Both accept `--json`; scripts
need not reconstruct relationships from lock and SBOM reports.

A managed build can reuse a provider result without adopting newly published
release bytes. Downstream release policy remains explicit: compare exact
prepared identities in capable admission CI, bind reviewed evidence to selected
configuration/files and artifact digests, and verify that binding on consuming
machines. Do not claim that a whole-lock checksum describes only the selected
producer inputs, or infer equal output bytes merely from input comparison.
