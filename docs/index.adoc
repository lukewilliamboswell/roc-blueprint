[.lead]
roc-blueprint lets a project describe its development environments, the
commands that run in them, its sandboxed builds and its ordered workflows in
one typed file, `Blueprint.roc`. The file says where every program comes
from: a download checked against a digest the project commits, the machine
itself, or a pinned Nix package source. The `blueprint` command carries it
out, and starts Nix only for what a project takes from Nix.

.How to use this manual
****
Deciding whether to use Blueprint:: Start with <<what-blueprint-is>>.
Using it for the first time:: Follow <<get-started>>.
Writing a configuration:: <<write-blueprint-roc>> describes every setting, and
<<build-artifacts-and-run-workflows>> the sandboxed builds.
Looking up a command or variable:: See <<run-blueprint>>.
Describing release composition:: See <<artifact-bound-software-bills-of-materials>>.
Running a project where Nix is not installed:: Read <<work-without-nix>>.
Looking for a project to adapt:: Browse <<learn-from-the-examples>>.
Writing a provider or judging a design change:: Read
<<understand-the-architecture>> and <<the-spec-the-lock-and-providers>>.
Changing roc-blueprint itself:: Read <<contribute>>.
Releasing or looking after the repository:: Read <<maintain-and-release>>.
Upgrading:: See <<release-notes>>.
****
