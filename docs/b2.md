# B2: locked sources and sandboxed artifact builds

Source-only implementation based on B1 `c779c01`. No compiler/dependency pins or
repository `flake.lock` changed. This is **not release-qualified**: the unchanged
major-1 `ir-release` remains incompatible. This document records B2; the current
[B3 API](b3.md) supersedes its single-step `Plan` shape and adds workflows.
B4 handoff remains pending.

## Authoring and shared validation

`Source(name, ref)` declares a non-flake input; it does not fetch at compile time.
`Build(name, [Use(environment), Inputs(names), Needs(builds), Run(argv),
Output(relative_path)])` requires exactly one Use, Run and Output. Inputs and
Needs are optional, each at most once. Sources and artifact dependencies live
at separate read-only locations, never merged into the project directory.

IR **2.1** adds optional top-level `build_sources` and `builds`, with required
features `sources` and `builds`. Existing nested records keep their meanings.
The platform lowers at top level through `Project.validate`; runtime readers
call the same validator. Unknown required features and other majors fail.
Old major-2 documents without the new optional fields still decode.

Validation includes declaration uniqueness, references, relative output paths,
nonempty executable argv, NUL rejection and bounded acyclic build dependencies.
Limits: 1,024 builds/sources, 8,192 input/dependency references, 128 dependency
levels, 4,096 argv elements and 1 MiB argv bytes. `Project.build_closure` returns
a deduplicated dependency-first order. Environment inheritance remains
parent-first, child additions second, first-occurrence deduplication.

The checked-in [fixture](../fixtures/builds/README.md) covers file and directory
artifacts, a shared dependency graph, source access and failure cases.

## Importable pure API

`blueprint-ir-package/main.roc` exports `Ir`, `Project`, `Request`, `Plan`,
`Layout`, `Sexpr` and `Value`. `blueprint-nix-package/main.roc` exports
`NixBackend`, `Locks` and inspection-only `Backend` metadata.

- `Request`: `Generate`, `Shell(name)`, `Run(name, extra_argv)`, `Build(name)`.
- `Layout`: absolute normalized `project_root`, `workspace`, `generated_root`,
  `lock_path`. No fixed workspace name or assumed nesting depth.
- `Locks.decode(text)`: real bounded JSON parsing plus authority/native Nix graph
  validation. Not an opaque text wrapper.
- `NixBackend.preflight(ir, request, target, layout)`: validate the request before
  lock observations/effects; shared with planning.
- `NixBackend.plan(ir, request, target, layout, locks)`: files, exact process argv,
  unique dependency-first `Plan.artifacts` (also across all builds for Generate),
  and materialization operations.
- `Plan.artifacts`: name, Nix installable, declared output and dependency names.
  The executor resolves the selected installable using the planned Nix command;
  store paths are never guessed. Dependency records describe the graph, not
  invented resolved store paths.
- Operations: `VerifyLocal({path, nar_hash})`, then, for each explicit build,
  `Snapshot({root, destination, exclude})`. These are compiled-in planner results,
  not instructions accepted from serialized configuration.
- `NixBackend.update_files` and `local_checks`: prepare and preflight an explicit
  update. After Nix resolves inputs, `Locks.from_nix(ir, layout, text)` validates
  and canonicalizes those observations; `Locks.encode` produces authority bytes.
- `Locks.derive`: validate supplied pins against declaration/ordered-overlay
  identity and derive a rebased native lock plus local verification operations.

`render`/`render_environment` remain inspection conveniences sharing the renderer.
An inspection flake cannot execute a build without planned materialization.
The old trusted-byte `render_files` interface was removed. The independent
[consumer](../fixtures/consumer/main.roc) imports the new APIs directly, without
Blueprint subprocesses, CLI state or an effectful backend package.

Provider/capability checks cover the requested environment/build closure. An
unrelated Guix environment does not force a provider switch or block a selected
Nix request. Whole-project structure, required features, supported declarations,
Raw and target validation still apply. Full requests check all referenced
environments. Missing native packages fail in Nix, without translation/fallback.
No backend autodetection, registry, Guix executor or workflow implementation exists.

## One authority, explicit update

Default authority is `Blueprint.lock`: a version-1 JSON envelope containing
input/ordered-overlay identities and a native version-7 Nix graph. It is not the
repository's toolchain `flake.lock`. B1 raw project locks need explicit update.

```sh
blueprint update
blueprint gen
blueprint run check
blueprint build app
```

Only `update` initializes/replaces authority. Normal generation/shell/task/build
operations require matching existing pins and never invoke lock/update or write
authority. Generated `flake.lock` files are derivatives; Nix receives both
`--no-update-lock-file` and `--no-write-lock-file`. Stable named declarations
remain present across selected closures; unselected overlays are not applied.
Changing ordered overlay identity requires explicit update.

Lock decoding validates immutable fetch identities/hashes, field types, native
root/edges/follows and declaration bindings. JSON has bounded size/depth/nodes;
Nix graphs allow at most 4,096 nodes with a shared 16,384-edge visit budget,
completed-edge memoization and cycle/depth checks. Unknown fetch attributes or
unsupported reference options fail rather than being guessed. Hosted originals
and locked nodes must have the same effective host, including omitted defaults:
`github.com`, `gitlab.com`, `git.sr.ht` (verified against
[Nix 2.34.8 fetchers](https://github.com/NixOS/nix/blob/2.34.8/src/libfetchers/github.cc)).

Supported references include project-relative `path:` subtrees, hosted
GitHub/GitLab/SourceHut references, supported remote Git/HTTP tarballs, and registry
flake references for flake inputs. Local Git/file URLs, absolute local paths,
parent traversal and unsupported URL options are rejected. Authority stores local
relative identity plus NAR content hash, never the checkout's absolute path.
Derivation locks translate these paths to the caller root without changing pins.
Every local input is checked before ordinary staging, even when Nix already has
its previous content cached. Changed content requires explicit update; there is
no live-tree fallback.

Update checks local filesystem safety before staging/fetching, validates the
replacement, then compare-and-swaps authority under a parent-directory flock.
Concurrent updates sharing authority cannot silently roll back another result.
Normal writes use rename rather than truncating hard-linked destinations.
Callers must serialize use of the same generated workspace and must not mutate
source trees or path components concurrently with materialization. This is not
a filesystem transaction against arbitrary external writers.

## Layout and execution

The reference CLI accepts:

| Variable | Default / resolution |
|---|---|
| `BLUEPRINT_ROOT` | Invocation directory; a relative override is invocation-relative |
| `BLUEPRINT_WORKSPACE` | `.blueprint`, relative to selected root |
| `BLUEPRINT_GENERATED_ROOT` | Workspace; a relative override is root-relative |
| `BLUEPRINT_LOCK` | `Blueprint.lock`, relative to selected root |
| `BLUEPRINT_TARGET` | `x86_64-linux`, must be declared |
| `ROC` | `roc` on PATH; relative executable paths are invocation-relative |

Local source paths and task working directories resolve against project root.
Out-of-tree workspace/generated roots and relocated authorities are tested.
Pure preflight/update checks reject collisions between actual generated files
(`flake.nix`, `flake.lock`, and `build-runner.py` when needed) and workspace,
snapshot or authority paths, before any materialization. A generated directory
may still contain a nonconflicting workspace.
The Nix package still provisions the pinned compiler. Standalone loading checks
its version and gives actionable missing/incompatible-compiler and unsupported
execution-host diagnostics. Help/version remain available without configuration.

Every explicit build snapshots current working-tree files, including untracked
and task-generated files. Exclusions are all VCS metadata basenames
(`.git`, `.hg`, `.svn`, `.jj`), caller workspace/generated roots, authority, and
all declared local input trees (including local package sets/overlays). No
artifact-name cache survives intervening task edits. Nix may reuse identical
materialized inputs. The initial filesystem policy rejects **all symlinks and
special files**, including nested source/output links, rather than guessing safe
link targets. Ordinary regular project files are included: keep secrets outside
the project or within excluded trees; snapshotting is not a secret detector.

The derivation copies the filtered immutable project snapshot into writable work.
It invokes Run with exact argv through Python, without implicit shell parsing.
Selected tools plus backend Python/coreutils/bash runner tools form PATH.
`BLUEPRINT_INPUTS/<name>` exposes declared locked sources and
`BLUEPRINT_ARTIFACTS/<name>` exposes exactly each needed artifact. Both locations
are immutable store trees, separate from work. The output must be a contained,
symlink-free regular file/directory at the declared relative path; the runner
copies only it to `$out`. Missing output, escaping/replaced ancestors, special
files and direct `$out` writes fail.

## Isolation: enforcement and evidence

Build requests currently require local **x86_64 Linux**. Nix uses ordinary,
non-fixed-output derivations: fetching pinned sources/tool dependencies occurs
separately from user Run. Build argv requests `sandbox=true` and
`sandbox-fallback=false`, but client settings alone are not evidence of daemon
policy (untrusted overrides can be ignored).

Snapshot additionally publishes `destination + ".isolation.json"`, containing
caller mount/network namespace identities from `/proc/self/ns`. These runtime
observations are separate from project bytes. Before copying work or executing
Run, the runner requires both namespaces to differ from the caller; missing,
malformed, unavailable or shared identities fail with a daemon-policy diagnostic.
Interrupted snapshot publication removes the old witness, failing closed.
Namespace identities are stable observations, not per-build cache-busting nonces.
Build argv disables remote builders with `--builders ""`; container topology
beyond this local contract is not qualified.

The integration gate also reads a unique undeclared host file and connects to a
live local TCP listener on the host as positive controls, before and after the
same probes are denied inside a newly executed user derivation. It separately
runs the production runner unsandboxed and proves Run is never reached. This is
actual host-file/network evidence, not merely an assertion about flags. Trusted
Nix daemon/kernel/package sources remain prerequisites; configuration compilation
and ordinary tasks themselves are **not sandboxed**.
